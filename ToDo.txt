YACYAML To Do
=============

In priority order: things that are wrong or untested first, then features, then
ideas.


YAML 1.2.2 update
-----------------

- Move to the 1.2 Core schema (spec 10.3.2), or add it as an option?  Scalars
  use the 1.1 rules (http://yaml.org/type/): y/n/yes/no/on/off booleans, base
  60 numbers, 0b binary, leading-zero octal, '_' in numbers.  Core has none of
  those; it adds 0o octal and exponents with no decimal point (1e3).

- Floats: the expression is the 1.1 spec's.  It accepts '.' and repeated dots
  ('1.2.3' decodes as 1.2) and rejects '_' in the fraction, though the spec's
  own example (685.230_15e+03) has one.  The 1.2 expression doesn't.  (PyYAML
  part-fixed this: https://github.com/yaml/pyyaml/pull/497.)  The two float
  tests lack the newlines between their lines, so they don't test floats.

- Integers over 64 bits (including base 60) stay strings, with a warning.
  NSDecimalNumber could hold them exactly (about 39 digits).

- Archiving: strings that 1.2 parsers read as other types but we read as
  strings (1e3, 1.5e3, 0o17, 08) are written unquoted.  Quote anything either
  schema would resolve differently.  NSDate is a plain timestamp (1.1; Core
  reads a string).  An explicit !!timestamp, perhaps optional, would round-trip
  dates in parsers that know it, at the cost of noise.

- A scalar whose content doesn't match its explicit tag (!!int abc) silently
  becomes a string.

- libYAML is a 1.1 parser (NEL, LS and PS are line breaks) that accepts %YAML
  1.2.  Run the yaml-test-suite to see how far from 1.2.2.


Swift
-----

- Swift overlay (Swift source in the library) for what NSKeyedArchiver has in
  Swift: generic, typed unarchivedObject(ofClass:from:) -> T? (it returns Any
  for now), and Codable support (encodeEncodable, decodeDecodable,
  decodeTopLevelDecodable).  Reuse the archiver and unarchiver: no rewrite, and
  no Encoder that writes libyaml events directly.
  - First: bridge through PropertyListEncoder and PropertyListDecoder.  Loses
    declaration order (it goes through dictionaries).  An explicit encodeNil
    comes out as the string "$null": map it to NSNull and back.  (A nil
    optional is never encoded, by any encoder: Swift skips it.)
  - Then: our own Encoder and Decoder that build and read the Foundation
    object tree for the existing archiver.  Native nil, declaration order (an
    ordered mapping class that writes its keys in order), key conversion,
    userInfo, errors with coding paths.

Options and ideas
-----------------

- Make AllowScalarAnchors the default?  It only anchors a scalar when that is
  smaller, so output grows by at most a character or two, but it is harder for
  a person to read and edit.

- DisallowExplicitTags options (archiver and unarchiver): plain YAML with no
  explicit tags.  Implies DisallowLocalTags, which is still needed alone for
  data with NSData, NSSet or !!timestamp but no application classes.
  - Archiving: raise in pass 1 for any object written with an explicit tag
    (YACYAMLArchivingTag non-nil and ...CanBePlainImplicit NO): NSData, NSSet,
    !ClassName classes, custom classes that don't declare their tag implicit.
    Dates are written as plain timestamps, which 1.2 Core reads as strings.
  - Unarchiving: ignore every tag (hook: _shouldIgnoreTag:), so none can cause
    a class to be instantiated.  !!binary comes back as a string, !!int "5" as
    "5", !!set as a dictionary, and !!merge << doesn't merge.  Ignore or raise?

- Presentation options on the archiver (libyaml supports all of them): multi-line
  strings as literal (|) or folded (>) blocks, not single-quoted with a blank
  line per newline; flow style for short collections ([1, 2, 3]); width
  (hard-coded 72), indent, unicode or escapes, canonical; sorted mapping keys
  (see the commented-out OrderMappingContentsByKey).

- Parse scalars (especially dates) with a proper parser, not regexes.  (Regexes
  are easy to check against the specs.)
